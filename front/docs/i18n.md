# Multilingual (FR / EN) — how it works

Homemade system (COS-155), zero external library. Live FR ↔ EN switching
(re-render, no reload): text, dates and numbers. Currency is fixed: EUR.

## Architecture

```
front/src/text/
├── fr/<zone>.ts     ← source of truth (11 zones: app, categories, common, dashboard,
│                       exceptionals, login, navBar, spendingSearch, spendings, statistics)
├── en/<zone>.ts     ← mirror typed `typeof fr` → a missing key fails the build
└── index.ts         ← { fr, en } dictionary + Dictionary / TextZone types

front/src/i18n/
├── config.ts             ← SUPPORTED_LOCALES, DEFAULT_LOCALE ("fr"), LOCALE_LABELS,
│                            NUMBER_LOCALES (fr-FR / en-US), localStorage key
├── LocaleContext.tsx     ← LocaleProvider (mounted in app/providers.tsx) + useLocale()
├── useTranslations.ts    ← useTranslations("<zone>") → that zone's object, active locale
├── useDateLocale.ts      ← active date-fns locale (+ DATE_FNS_LOCALES for pure code)
├── useFormat.ts          ← euro / euro0 / pct1 / splitAmount / numberLocale, reactive
├── interpolate.ts        ← renders "{token}" templates (see below)
├── pickSupportedLocale.ts← browser languages → supported locale (fr fallback)
├── LocaleUserSync.tsx    ← applies user.language (backend) to the context, private layout
└── useUpdateLanguage.ts  ← switch + persistence (optimistic, reverts on failure)
```

FR/EN parity is compiler-enforced: every EN file is typed against its FR
counterpart (`const spendings: typeof frSpendings = {…}`). A missing key, an
extra key or a diverging function signature fails `tsc`.

## Locale resolution and persistence

- **Signed-in init**: `user.language` (backend, cross-device source of truth)
  ?? `localStorage` ?? browser languages ?? `fr`.
- **Anonymous init** (login, about): `localStorage` ?? browser ?? `fr`.
- **Switching** (Language submenu in the UserMenu): optimistic context update +
  localStorage + `PATCH /users/me` (session + CSRF); revert + error toast if the
  call fails.
- **Signup**: `pickSupportedLocale(navigator.languages)` goes into the payload.
- The server always renders FR; the stored locale applies after hydration
  (brief FR flash possible on a hard reload in EN — accepted trade-off, no
  SSR cookie/middleware).

## Usage rules in components

1. **Never import `@text/<zone>` directly** — always the hook:
   ```tsx
   const spendings = useTranslations("spendings");
   const { summary: t } = spendings;
   ```
2. **Never import `@lib/format` directly** (raw non-reactive helpers, reserved
   for non-React code) — always `useFormat()`:
   ```tsx
   const { euro, euro0, pct1, splitAmount, numberLocale } = useFormat();
   ```
3. **Dates**: `const dateLocale = useDateLocale();` then
   `format(date, "d MMMM", { locale: dateLocale })`.
4. **No text evaluated at import time.** Hooks cannot run at module scope: no
   zone destructure at the top of a file, no zod schema with messages at module
   scope (→ `makeSchema(t)` factory called inside the component), no module
   constant built from text.
5. Pure code (non-hook helpers): pass the locale/texts **as parameters**
   (e.g. `groupByMonth(items, locale)`, `humanSize(bytes, units, locale)`).

## Sentences with interleaved data — `{token}` templates

ICU MessageFormat syntax (as in react-intl/next-intl), rendered by
`interpolate()`: **one key = one sentence**, word order lives in the
dictionary, styling stays in the JSX.

```ts
// fr/dashboard.ts
remainingSentence: "Il reste {perDay}/jour à dépenser d'ici le {date} pour rester dans le budget.",
// en/dashboard.ts
remainingSentence: "{perDay}/day left to spend until {date} to stay on budget.",
```

```tsx
{interpolate(t.remainingSentence, {
  perDay: <b className="num font-semibold text-ink">{euro0(perDay)} €</b>,
  date: <b className="font-semibold text-ink">{lastDayLabel}</b>,
})}
```

A token with no supplied value renders as-is (`{typo}`): a typo shows up on
screen instead of being swallowed.

### Plurals

No ICU plural syntax (overkill for 2 locales): a function picks the variant —
of a template or of a full string:

```ts
// en — template variant (styled data inside)
usage: (count: number) =>
  count === 1 ? "{share} of spendings{dot}{count} time" : "{share} of spendings{dot}{count} times",
// en — plain string (no styled interleave)
transactions: (count: number) => `${count} transaction${count === 1 ? "" : "s"}`,
```

When FR is invariant but EN pluralizes, FR keeps the parameter (prefixed `_`)
so both signatures stay identical.

## Adding a language

1. `src/text/<locale>/`: mirrors typed `typeof fr` (the compiler lists
   everything that is missing).
2. `config.ts`: add the locale to `SUPPORTED_LOCALES`, `LOCALE_LABELS`
   (endonym), `NUMBER_LOCALES`.
3. `useDateLocale.ts`: map the date-fns locale.
4. `text/index.ts`: wire the modules into `dictionaries`.
5. Back: widen the `@IsIn([...])` of `UpdateUserDto`.

The UserMenu Language submenu is data-driven on `SUPPORTED_LOCALES` — nothing
else to touch.

## Known pitfalls

- `LocaleProvider` must **never** remount the tree (`key={locale}`): that
  would reset `AuthProvider` to its server value and `LocaleUserSync` would
  cancel the switch (historical bug of the COS-155 v1).
- `MONTHS_FR` (`statistics/helpers/statisticsData.ts`) is **wire format** (the
  API emits its month keys in French), not copy — do not "translate" it.
  Display goes through `monthShortLabels(locale)`.
- Only user-facing copy belongs in the dictionaries. Code itself — including
  comments — is English-only.
